# Data

This folder is intentionally empty in version control. Everything here is
either downloaded or generated by the notebooks and is too large / too
easily regenerated to commit.

## What lives here at runtime (not committed)

| Path | Produced by | Notes |
|---|---|---|
| `spider-data/` | `notebooks/phase0_setup.ipynb`, Task 3 | Cloned from `minktn/spider-data` on Hugging Face; also loadable via `datasets.load_dataset("xlangai/spider")`. Contains `tables.json`, `train_spider.json`, `dev.json`, and one `.sqlite` file per `db_id`. |
| `train.jsonl` / `val.jsonl` / `test.jsonl` | `notebooks/phase0_setup.ipynb`, Task 5 | Spider's raw (schema, question, gold SQL) triples reformatted into the project's instruction-tuning prompt format via `schema_to_text()` / `build_prompt()`. Train/val split is a 92/8 split of Spider's `train_spider.json` (seed=42); test is Spider's `dev.json`, unmodified, per the PRD's instruction to keep it comparable to published Spider results. |
| `train_augmented_phase2.jsonl` | `notebooks/phase2_iteration.ipynb`, Task 2 | `train.jsonl` plus targeted oversampling of self-join and NOT-IN-subquery examples (detected via `detect_self_join()` / `detect_not_in_subquery()`), 9,380 rows total. Every row is reproducible by rerunning Task 2 against the same seed. |

## Why these aren't committed

- **Size**: the augmented training set alone is ~9,380 rows of full schema
  text + gold SQL; the raw Spider `.sqlite` databases add up to hundreds of
  MB across all `db_id`s.
- **Reproducibility**: every file above is fully deterministic from a
  notebook cell plus a fixed seed (`42` throughout). Regenerating is a
  matter of rerunning the relevant notebook top to bottom — there's no
  manual step or non-reproducible randomness involved.
- **Provenance**: Spider itself is a third-party dataset with its own
  license; redistributing a full copy inside this repo isn't necessary
  when the notebooks pull it fresh from its official sources.
